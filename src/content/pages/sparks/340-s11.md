# S11 · Notes collection

Add your notes to your Final Project: a notes index, and a page for every Spark and Prototype you've done, checked by a schema that requires all five sections. Plan on 15–30 minutes, plus fixing any old notes the build rejects. It's due before class on Wed Dec 2 and graded Complete / Not yet straight from your repo, so there's nothing to submit.

The schema is a rule for your own writing, and the build tells you which old notes break it. Fix those in your words, not Claude's. The work goes in `final-project/`; this Spark's folder holds only its `NOTES.md`. The step most people miss: the loader reads *every* `NOTES.md`, including this Spark's, so the build fails until this one is complete too. Write it before you push.

## 1. Intent

In `sparks/s11-notes-collection/NOTES.md` **Intent**: who will read your notes pages (your instructor, a future employer, you), and what should they get from them?

## 2. Spec: the "done" list

Your Spark is done when:

<!-- done:start -->

- [ ] `final-project/src/notes-loader.js` is the course's notes loader from the unit page, unchanged.
- [ ] `final-project/src/content.config.js` defines a `notes` collection with that loader and a zod schema that requires `title`, `kind`, and all five sections, each with an error message that names the section.
- [ ] Every Spark and Prototype `NOTES.md` in your repo passes the schema. Any that didn't, you fixed yourself, and `NOTES.md` lists which.
- [ ] A notes index page lists every note by title, grouped into Sparks and Prototypes, in order.
- [ ] `src/pages/notes/[id].astro` builds one page per note with `getStaticPaths()`, with one `<h1>`, the note's content, and a link back to the index.
- [ ] The nav has a Notes link, and every link uses `BASE_URL` (your `url()` helper).
- [ ] You emptied one section on purpose, read the build error, and put it back.
- [ ] `sparks/s11-notes-collection/NOTES.md` covers every section, in your own words (the build checks it now).
- [ ] It's committed and pushed, **Build and deploy** is green, and `…/dight340/final-project/notes/` loads.

<!-- done:end -->

## 3. Generate

Plan mode first. Give Claude the "done" list, and tell it you'll paste the loader yourself (from the [unit page](/340/units/astro-collections/)). Ask for the schema first, and build: let the build tell you which notes need fixing before you write any pages. Then the index, then `[id].astro`.

Claude mustn't write your old notes' missing sections (`AGENTS.md` says so, and it should refuse). It can tell you which ones are missing.

**Watch for:** an offer to add frontmatter to every `NOTES.md` (you don't need it), sections marked `.optional()`, an unsorted index, links without the base, and a second `<h1>` on note pages. If you catch one, it's a good entry for "Accepted / changed / rejected."

## 4. Verify

- `npm run build` in `final-project/`: count the notes pages against your `sparks/` and `prototypes/` folders.
- Empty one section, build, read the error aloud. Put it back.
- `npm run preview`: open the index and three notes with the keyboard. Back link? One `<h1>` each (check the accessibility tree)?
- After you push: **Build and deploy** green, and the live notes pages load.

## 5. Explain

Finish `NOTES.md`. Read one line of your schema in plain words, and say which old note failed and what you added. [`/dig-deeper`](/340/skills/dig-deeper/) on `getStaticPaths()` and when it runs is a good dig-deeper starting point.

Then run [`/check`](/340/skills/check/) `sparks/s11-notes-collection` and paste in the "done" list above (the **Copy** button copies it).
