# S02 · Render the party

**Concept:** the DOM, re-run: creating elements from data, and handling events on semantic buttons.
**Time:** 15–30 minutes in studio, and due before class.

You've practised the DOM by hand. Now drive Claude Code through it, under the **Learning** output style: it will leave a small decision for you to write (marked `TODO(human)`). Write that part yourself.

## 1. Intent

Before you start, write two or three sentences in your `NOTES.md` **Intent** section: what this page does, and for whom. For example, a trainer checking which party members still need training.

## 2. Spec: the "done" list

Your page is done when:

<!-- done:start -->

- [ ] `sparks/s02-render-party/` has an `index.html` and a JavaScript file loaded with `defer` (or `type="module"`).
- [ ] The party is an array of objects in JavaScript (copy yours from `archive/party.js` or start fresh), and the page builds the list from that array. No party members are hard-coded in the HTML.
- [ ] Each party member has at least one real `<button>` that does something (for example: level up, mark as fainted, or remove). It works with a mouse **and** with Tab + Enter/Space.
- [ ] When something changes, the visible text changes too, not just a color.
- [ ] Focus stays visible, and stays somewhere sensible after a button removes an item.
- [ ] The console shows no errors. The code uses `const`/`let` and `===` only.
- [ ] Your hub `index.html` links to it under Sparks.
- [ ] `NOTES.md` covers every section, in your own words.
- [ ] It's committed, pushed, and the live page loads at `…/dight340/sparks/s02-render-party/`.

<!-- done:end -->

## 3. Generate

Use plan mode first: give Claude your intent and the "done" list, and agree on the plan before it writes code. Keep requests small. When it leaves a `TODO(human)`, write that part yourself, then tell it you're done.

**Watch for:** clickable `<div>`s or `<span>`s instead of buttons, `innerHTML` with data mixed into strings, and focus that vanishes when an item is removed. If you catch one, it's a good entry for "Accepted / changed / rejected."

## 4. Verify

- Open the live page with the console open. No errors?
- Unplug the mouse (figuratively): do everything with Tab, Enter, and Space.
- Change one object in the array and reload. Does the page follow the data?

## 5. Explain

Finish `NOTES.md`. Include what you wrote for the `TODO(human)` and why you chose that approach over another. [`/dig-deeper`](/340/skills/dig-deeper/) on `createElement` vs `innerHTML` is a good dig-deeper starting point.

Then run [`/check`](/340/skills/check/) `sparks/s02-render-party` and paste in the "done" list above (the **Copy** button copies it).
