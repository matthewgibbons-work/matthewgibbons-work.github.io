# S10 · Astro Final Project

**Concept:** Astro pages, layouts, build-time data, and links that work under a base path.
**Time:** 15–30 minutes in studio (after the kit update), and due before class.

This is where your Final Project starts living. Create an Astro site in `final-project/`, give it the bones from your intent brief (a layout, a home page, and one page of real data), and get it live. It's small on purpose: a deployed skeleton you'll add to every session. The site lives in `final-project/`; this Spark's own folder holds only its `NOTES.md`. From today Claude uses the **Explanatory** output style, so there are no `TODO(human)` gaps. Read every `★ Insight`, and push back when you disagree.

## 0. The kit update (do this first)

Download [`dight340-update-nov23.zip`](/downloads/dight340-update-nov23.zip) and double-click it. In your `dight340` session, paste:

```text
My instructor asked me to update the course kit. Copy everything in ~/Downloads/dight340-update-nov23/ into the root of this repo, replacing what's there, including the hidden .claude, .github, and .gitignore. Then show me git status.
```

GitHub Desktop should show two changed files: `.claude/settings.json` (the output style) and `.github/workflows/deploy.yml` (Astro support). Commit "Update course kit for Nov 23", push, and open a **new** session so the Explanatory style loads.

## 3. Generate

Plan mode first: give Claude your intent brief (`sparks/s09-final-project-intent/INTENT.md`) and the "done" list, and agree on the plan. Ask for the scaffold first, with exactly this command (`--no-git` matters: your repo already is one): `npm create astro@latest final-project -- --template minimal --no-git --install`. Then the layout, then each page. With Explanatory on, Claude explains as it goes; if an explanation doesn't make sense, ask before you accept.

The scaffold adds its own `final-project/AGENTS.md` with Astro's notes for agents. Keep it for now: in S14 you'll rewrite it as your project's own.

**Watch for:** root-relative links (they work in dev and break on Pages), a hard-coded `base`, a data fetch in a `<script>` tag instead of the frontmatter, no `response.ok` check, and Claude restructuring folders outside `final-project/`, and a second `.git` folder inside `final-project/` (GitHub Desktop then can't see its files). If you catch one, it's a good entry for "Accepted / changed / rejected."

## 4. Verify

- In `final-project/`, `npm run build`, then `npm run preview`: every link works?
- Search `final-project/src` for `href="/` and `src="/`. None?
- View Source on your data page: is the data in the HTML? Then turn JavaScript off and reload.
- After you push, open `…/dight340/final-project/` and click every nav link. Then check your `archive/` pages and an older Spark still load.

## 5. Explain

Finish `NOTES.md`. Include one `★ Insight` you agreed with and one you questioned, and what "build time" means for your data page in your own words. [`/dig-deeper`](/340/skills/dig-deeper/) on `import.meta.env.BASE_URL` is a good dig-deeper starting point.
