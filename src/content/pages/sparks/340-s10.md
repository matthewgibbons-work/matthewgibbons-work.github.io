## The problem

Your party pages are Vite apps. That was right for one interactive page, and it's wrong for a site: **with JavaScript off, the page is blank**; the party arrives after a **spinner**, because the browser fetches it on every visit; a second page means **a second project** and the nav copied into it; and a link written `href="/first-twelve/"` works in dev and **404s on GitHub Pages**.

Your job is the "Wanted" column: a new Astro practice site in `sparks/astro-practice/`, with a layout, a home page, and a page of PokéAPI data fetched at build time, live on GitHub Pages. Plan on 15–30 minutes after the kit update. It's due before class on Mon Nov 30 and graded Complete / Not yet straight from your repo, so there's nothing to submit. Do the Nov 23 kit update first (step 0).

Use the unit's [At a glance](/340/units/astro-intro/#at-a-glance) table and Live demo as your reference. It's small on purpose: S11, S12, and S13 each add to this site (a collection, an island, tests), so it's where you practise each Astro idea before you use it on your Final Project. The site lives in `sparks/astro-practice/`; this Spark's own folder holds only its `NOTES.md`. From today Claude uses the **Explanatory** output style, so there are no `TODO(human)` gaps: read every `★ Insight`, and push back when you disagree. The step most people miss is the base path: a link written `href="/…"` works in dev and 404s on GitHub Pages.

## 0. The kit update (do this first)

In your `dight340` session, run [`/update-kit`](/340/skills/update-kit/). Before it changes anything it tells you what it will do. If it asks about a file you changed (often `.gitignore`), choose **show me the difference**, then decide.

GitHub Desktop should show three changed files: `.course-kit-version`, `.claude/settings.json` (the output style) and `.github/workflows/deploy.yml` (Astro support). Commit "Update course kit for Nov 23", push, and open a **new** session so the Explanatory style loads.

## 1. Intent

Create `sparks/s10-astro-practice/` with its own `NOTES.md`. In its **Intent**: who visits your party site, and what should they be able to read with JavaScript off?

**Predict before you prompt.** Under your intent, add a line that starts `Prediction:`. For each row of the sketch, what do you expect Astro to use to fix it (a folder, a file, a part of a `.astro` file, a variable)? A guess is fine; you'll check it in step 5.

## 3. Generate

Plan mode first: give Claude your intent and the "done" list (not your prediction: that's for you), and agree on the plan. Ask for the scaffold first, with exactly this command (`--no-git` matters: your repo already is one):

```text
npm create astro@latest sparks/astro-practice -- --template minimal --no-git --install
```

Then the layout, then each page. With Explanatory on, Claude explains as it goes; if an explanation doesn't make sense, ask before you accept. The scaffold adds its own `AGENTS.md` with Astro's notes for agents; leave it.

**Watch for:** root-relative links (they work in dev and break on Pages), a hard-coded `base`, a data fetch in a `<script>` tag instead of the frontmatter, no `response.ok` check, Claude restructuring folders outside `sparks/astro-practice/`, and a second `.git` folder inside it (GitHub Desktop then can't see its files). If you catch one, it's a good entry for "Accepted / changed / rejected."

## 4. Verify

Walk the sketch's five rows on your own site:

- Turn JavaScript off and reload each page. Does everything read?
- View Source on your data page: is the party in the HTML, with no spinner?
- Count the files in `src/pages/` and `src/layouts/`. Is the nav written once?
- In `sparks/astro-practice/`, `npm run build`, then `npm run preview`: every link works? Search `src` for `href="/` and `src="/`. None?
- After you push, open `…/dight340/sparks/astro-practice/` and click every nav link. Then check your `archive/` pages and an older Spark still load.

## 5. Explain

**Check your prediction.** Under your `Prediction:` line, add `What it used:`: what Astro actually used for each row of the sketch, where your guess matched, where it didn't, and why.

Then finish `NOTES.md`. Include one `★ Insight` you agreed with and one you questioned, and what "build time" means for your data page in your own words. [`/dig-deeper`](/340/skills/dig-deeper/) on `import.meta.env.BASE_URL` is a good dig-deeper starting point.
