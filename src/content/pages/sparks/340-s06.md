# S06 · Trainer card

Build a card for one Pokémon you're training, as your first Svelte component: its name, its level, buttons to change the level, and something worked out from the level, such as levels until it evolves. Plan on 15–30 minutes after the kit update. It's due before class on Mon Nov 9 and graded Complete / Not yet straight from your repo, so there's nothing to submit. Do the Nov 4 kit update first (step 0), in its order.

It's small on purpose, so you can name what every line does. The kit update adds the **build-and-deploy workflow**: from now on GitHub builds every Vite and Svelte folder in your repo, so your S05 page goes live too. Claude is still on the **Learning** output style: write any `TODO(human)` yourself (the derived value or the lower limit are likely). The step most people miss is the Pages setting: switch **Source** to **GitHub Actions** before you push the update.

## 0. The kit update (do this first, in this order)

1. On GitHub, open your `dight340` repo → **Settings** → **Pages** → **Source**, and choose **GitHub Actions**. (Your site stays up; it just stops publishing straight from `main`.)
2. Download [`dight340-update-nov04.zip`](/downloads/dight340-update-nov04.zip) and double-click it. In your `dight340` session, paste:

   ```text
   My instructor asked me to update the course kit. Copy everything in ~/Downloads/dight340-update-nov04/ into the root of this repo, replacing what's there, including the hidden .claude, .github, and .gitignore. Then show me git status.
   ```

3. In GitHub Desktop the only new file should be `.github/workflows/deploy.yml`. Commit "Add the deploy workflow", and push.
4. On GitHub → **Actions**, watch **Build and deploy** run. When it's green, open your hub and your S05 page.

## 3. Generate

Plan mode first: give Claude your intent and the "done" list, and agree on the plan before it writes code. Ask for the project first, strip the template, then the component. When Claude leaves a `TODO(human)`, write it yourself, then run [`/dig-deeper`](/340/skills/dig-deeper/) on what you wrote.

**Watch for:** an `$effect` that keeps one piece of state in step with another (use `$derived`), buttons labelled `+` and `−`, Svelte 4 syntax, a TypeScript template you didn't ask for, and the template's `/icons.svg` link. If you catch one, it's a good entry for "Accepted / changed / rejected."

## 4. Verify

- `npm run dev`, then keyboard only: level up until the derived value changes. Is focus still on the button?
- Level down to 1. Can you go further?
- In DevTools → Elements → **Accessibility**, select each button. What's its name?
- After you push, check **Actions**: both **Checks** and **Build and deploy** green? Then open the live page.

## 5. Explain

Finish `NOTES.md`. Name each rune in your component and say in a sentence why it's that rune and not another. Then ask Claude to show you, in the chat only, how your component's `<script>` would look with `lang="ts"` and type annotations (don't keep it), and write one annotation out in plain words. [`/dig-deeper`](/340/skills/dig-deeper/) on "when not to use `$effect`" is a good dig-deeper starting point.

Then run [`/check`](/340/skills/check/) `sparks/s06-trainer-card` and paste in the "done" list above (the **Copy** button copies it).
