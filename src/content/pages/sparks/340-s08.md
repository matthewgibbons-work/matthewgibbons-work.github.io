# S08 · Party components

## The problem

Your S07 party page works. Now a friend wants to add a **Level up** button to each member and a second **Box** panel beside the party. **Right now** everything lives in one long `App.svelte`: to change one member's row they have to find it among the fetch code, the focus code, and the markup for everything else; any line in the file can change the party, so when the levels come out wrong there's no one place to look; and a second panel means copying the first one's markup. The page is fine for visitors. It's hard for the next person to change, and next week that's you.

Your job is the "Wanted" column: the same page, split into components. A visitor sees and hears the same page as before, plus the new Level up buttons and a heading on the panel. Plan on 15–30 minutes. It's due before class on Wed Nov 18 and graded Complete / Not yet straight from your repo, so there's nothing to submit. **Before Wednesday, read the [Final Project](/340/final-project/) brief** (out Mon Nov 16): Wednesday's Spark is your intent brief for it.

The skill is in the seams: who owns the party, what each component is given, and how a button press in one component becomes a change in another. Add the Level up button from the problem as your second callback. PokéAPI has no level, so give each member a starting level in your data (5 is fine). You don't need to build the Box panel: putting the party in one `Panel` shows it's ready for a second. Claude is still on the **Learning** output style: when it leaves a `TODO(human)` (a callback, or where the focus code now lives), write it yourself. The step most people miss is the last row: focus after a remove has to move up to `PartyList`, which can see the other members.

## 2. Spec: the "done" list

## 3. Generate

Plan mode first: give Claude your intent and the "done" list (not your prediction: that's for you), and ask for the plan as a list of components with each one's props, before any code. Agree on who owns what. Then one component at a time, checking the page still works after each. When Claude leaves a `TODO(human)`, write it yourself.

**Watch for:** a child changing data it was handed (`pokemon.level++`, which works but warns in the **browser** console), `export let` or `createEventDispatcher` (Svelte 4), types of `any`, focus code left in the child where it can't see the other members, and S07's focus code finding "the next button" when each member now has two (Level up and Remove). If you catch one, it's a good entry for "Accepted / changed / rejected."

## 4. Verify

Walk the sketch's five rows on your own page:

- Open `PartyMember.svelte`: is a member's row all there, and nothing else?
- Search `PartyMember.svelte` for `splice`, `filter`, `++`, and `=` on a prop. Only callbacks? Then press every button with the browser console open. Any warnings?
- Hover a prop in VS Code with the Svelte extension (or ask Claude): what type does it say? Then pass a string where a number belongs and see whether it's underlined.
- Inspect the panel's heading: does the `<section>`'s `aria-labelledby` match its `id`?
- Keyboard only: remove every member. After each Enter, where is focus? Side by side with your S07 page, does it behave and read out the same?
