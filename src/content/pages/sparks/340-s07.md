# S07 · Party list

Show a party fetched from PokéAPI in Svelte, with a loading message, an error message, a message when it's empty, and a Remove button on every member. Plan on 15–30 minutes. It's due before class on Mon Nov 16 (there's no class Wed Nov 11) and graded Complete / Not yet straight from your repo, so there's nothing to submit.

It's S02 and S03 again, in Svelte, with no `render()` and no three loading flags: the blocks do it. Keep it to the list; adding by name and filtering are P3's job. Claude is still on the **Learning** output style: write any `TODO(human)` yourself. Where focus goes after a remove is a likely one, and you've solved it before. The step most people miss is the `{#each}` key: the page looks fine without one until a row holds something of its own.

## 3. Generate

Plan mode first: give Claude your intent and the "done" list, and agree on the plan before it writes code. Small steps: the project, then the fetch with `{#await}`, then the list and remove, then focus. Keep the terminal with `npm run dev` where you can see it: warnings appear there as soon as you save.

**Watch for:** an unkeyed `{#each}`, a clickable `<div>` (the terminal will tell you), `{#await}` with no `{:catch}`, the fetch tucked inside an `$effect`, and `await` in a `for` loop instead of `Promise.all`. If you catch one, it's a good entry for "Accepted / changed / rejected."

## 4. Verify

- Read the terminal after every save. Any `a11y_` lines?
- Misspell one name. Is there a message on the page?
- DevTools → Network → **Slow 4G**, reload: do you see the loading message? Set it back.
- Keyboard only: remove every member. After each Enter, press Enter again: does it remove the next one, or nothing? When the party is empty, where is focus?
