# S07 · Party list

## The problem

A trainer opens their party page on a slow phone connection. **Right now** the page is blank until everything arrives. If one name in the party is misspelled, the whole page stays blank and says nothing. The ✕ next to each member only works with a mouse, and after someone removes a member with the keyboard, focus drops back to the top of the page. Remove everyone, and it goes blank again.

## 3. Generate

Plan mode first: give Claude your intent and the "done" list (not your prediction: that's for you), and agree on the plan before it writes code. Small steps: the project, then the fetch with `{#await}`, then the list and remove, then focus. Keep the terminal with `npm run dev` where you can see it: warnings appear there as soon as you save.

**Watch for:** focus dropping to the page after a remove: with a keyed `{#each}`, the removed row takes its button with it, so move focus yourself after the page updates (`await tick()`, then `.focus()`); names capitalized with CSS only, so a screen reader hears "Remove eevee"; `bind:this` inside `{#await}` without `$state` (a `non_reactive_update` warning); an unkeyed `{#each}`, a clickable `<div>` (the terminal will tell you), `{#await}` with no `{:catch}`, the fetch tucked inside an `$effect`, and `await` in a `for` loop instead of `Promise.all`. If you catch one, it's a good entry for "Accepted / changed / rejected."
