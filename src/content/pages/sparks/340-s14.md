# S14 · Configure your agent

## The problem

A friend built the **League Roster**, a small Astro + Svelte site for their Pokémon club, fast, with Claude, and then handed it to you. It works in `npm run dev`. But the project tells Claude nothing about itself, so every time anyone asks for a change, Claude **copies whatever patterns are already there**, including the bad ones: links that 404 on GitHub Pages, a list with no keys, an `$effect` that sets state, a fetch that never checks `response.ok`. And the one job the club asks for every week (adding a trainer) gets **explained from scratch** every time.

Your job is the "Wanted" column: the League Roster's own `AGENTS.md` and one custom skill, written by you, then tested in a new session. Plan on 20–30 minutes, including a few minutes finding the project's habits. It's due the same day as class, Wed Dec 9 (the last day for new-system work other than the Final Project), and graded Complete / Not yet straight from your repo, so there's nothing to submit.

Claude can review and try your files, but the rules and the reasons are yours, which is why the course's `AGENTS.md` keeps it out of `AGENTS.md` and `.claude/` files. The step most people miss is testing in a **new** session, after Claude has read a file in the project: that's when your rules load.

## 1. Intent

Download [dight340-s14-roster.zip](/downloads/dight340-s14-roster.zip) and unzip it so the project is at `sparks/s14-configure-agent/roster/` (its `package.json` directly inside `roster/`). Create `sparks/s14-configure-agent/NOTES.md`. Then, in `roster/`, run `npm install`, `npm run build`, and `npm run preview`, and read its `README.md`.

In **Intent**: if a classmate picked up the League Roster tomorrow with Claude Code, what would you want Claude to know before it touched anything?

**Predict before you prompt.** Under your intent, add a line that starts `Prediction:`. Read `src/` for five minutes and list the habits you expect Claude to copy if you ask it to add a page (look at the links, the lists, the effects, the fetches). A guess is fine; you'll check it in step 4.

## 2. Spec: the "done" list

Your Spark is done when:

<!-- done:start -->

- [ ] `sparks/s14-configure-agent/roster/` holds the League Roster, and it builds (`npm run build`).
- [ ] `roster/AGENTS.md` is yours: 10–25 lines saying what the site is and for whom, where things live, the commands that prove it works (`npm run build`, `npx vitest run`), and at least three rules for habits you found in this project.
- [ ] Every rule is specific enough to check ("every `{#each}` has a key", not "write good code"), and at least one comes from something you saw break.
- [ ] `roster/.claude/skills/<name>/SKILL.md` has a `name`, a `description` that says when to use it, and instructions for a job the club would ask for more than once (for example `/new-trainer`, `/a11y-pass`, or `/check-links`). If it should never write `NOTES.md` or run git, it says so.
- [ ] You tested both in a **new** session: after Claude read a file in `roster/`, it could say your rules without opening `AGENTS.md`, your skill was in the `/` menu, and you ran it once.
- [ ] You asked Claude to add a page or a component, and wrote down whether it followed your rules or copied the old habits.
- [ ] You asked Claude to do something one of your rules forbids, and wrote down what happened.
- [ ] `NOTES.md`'s Intent has your `Prediction:` line, and under it a `What it used:` line comparing your guess with what Claude did.
- [ ] `sparks/s14-configure-agent/NOTES.md` covers every section, in your own words, and **Accepted / changed / rejected** gives the reason for each rule.
- [ ] It's committed and pushed.

## 3. Generate (Claude reviews; you write)

First, see the problem: in a new session, ask Claude to add a "Badges" page that lists each trainer's badges and links to it from the nav. Don't accept the change; read the diff and note which habits it copied. Then discard it.

Write `roster/AGENTS.md` and your `SKILL.md` yourself, in your editor or a text app; look at `.claude/skills/check/SKILL.md` for the format. Then, in a new session, paste:

```text
Read sparks/s14-configure-agent/roster/AGENTS.md and sparks/s14-configure-agent/roster/.claude/skills/ (don't edit them). Tell me which of my rules are ambiguous or can't be checked, which important thing about this project I left out, and whether my skill's description would make you use it at the right time.
```

Change what you agree with, yourself. Then try the skill.

**Watch for:** Claude offering to "improve" or rewrite either file (say no), rules copied from the course's `AGENTS.md` instead of found in this project, a skill so general it's just "help me", and a skill that would write `NOTES.md` sections. If you catch one, it's a good entry for "Accepted / changed / rejected."

## 4. Verify

Walk the sketch's five rows:

- Open a **new** session. Ask Claude to read `roster/src/pages/index.astro`, then: "What are this project's rules?" Does it list yours?
- Ask for the same Badges page again. Compare the diff with the first one: which habits did your rules stop?
- Ask for something one rule forbids (a link with a leading slash, say). Does Claude object, and quote your rule?
- Type `/`: is your skill there? Run it on something real.

## 5. Explain

**Check your prediction.** Under your `Prediction:` line, add `What it used:`: the habits Claude actually copied the first time, which ones your rules stopped the second time, and which ones got through anyway.

Then finish `NOTES.md`. For each rule, one line on what you saw in this project that made you write it. [`/dig-deeper`](/340/skills/dig-deeper/) on the difference between a rule in `AGENTS.md` and a hook (like the course's scope guard) is a good dig-deeper starting point.

Then run [`/check`](/340/skills/check/) `sparks/s14-configure-agent` and paste in the "done" list above (the **Copy** button copies it).
