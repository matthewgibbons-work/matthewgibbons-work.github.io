# S14 · Configure your agent

Write your Final Project's own `final-project/AGENTS.md` and one custom skill you'd actually use again, yourself, then test in a new session that Claude Code follows them. Plan on 15–30 minutes. It's due the same day as class, Wed Dec 9 (the last day for new-system work other than the Final Project), and graded Complete / Not yet straight from your repo, so there's nothing to submit. Both files also count toward your Final Project's AI use score.

Claude can review and try them, but the rules and the reasons are yours, which is why the course's `AGENTS.md` keeps it out of these files. The files go in `final-project/`; this Spark's folder holds only its `NOTES.md`. The step most people miss is testing in a **new** session, after Claude has read a file in `final-project/`: that's when your rules load. Next, the Final Project itself is due Wed Dec 16.

## 1. Intent

In `sparks/s14-configure-agent/NOTES.md` **Intent**: if a classmate picked up your Final Project tomorrow with Claude Code, what would you want Claude to know before it touched anything?

## 2. Spec: the "done" list

Your Spark is done when:

<!-- done:start -->

- [ ] `final-project/AGENTS.md` is yours (the template's version replaced): 10–25 lines saying what the site is and for whom, where things live, the commands that prove it works (`npm run build`, `npx vitest run`, `npx playwright test`), and at least three rules you learned the hard way this term.
- [ ] Every rule is specific enough to check ("every `{#each}` has a key", not "write good code").
- [ ] `final-project/.claude/skills/<name>/SKILL.md` has a `name`, a `description` that says when to use it, and instructions you'd run more than once (for example `/a11y-pass`, `/new-note`, or `/add-pokemon-page`). If it should never write `NOTES.md` or run git, it says so.
- [ ] You tested both in a **new** session: after Claude read a file in `final-project/`, it could say your rules without opening `AGENTS.md`, your skill was in the `/` menu, and you ran it once.
- [ ] You asked Claude to do something one of your rules forbids, and wrote down what happened.
- [ ] `sparks/s14-configure-agent/NOTES.md` covers every section, in your own words, and **Accepted / changed / rejected** gives the reason for each rule.
- [ ] It's committed and pushed.

<!-- done:end -->

## 3. Generate (Claude reviews; you write)

Write `final-project/AGENTS.md` and your `SKILL.md` yourself, in your editor or a text app; look at `.claude/skills/check/SKILL.md` for the format. Then, in a new session, paste:

```text
Read final-project/AGENTS.md and final-project/.claude/skills/ (don't edit them). Tell me which of my rules are ambiguous or can't be checked, which important thing about this project I left out, and whether my skill's description would make you use it at the right time.
```

Change what you agree with, yourself. Then try the skill.

**Watch for:** Claude offering to "improve" or rewrite either file (say no), rules copied from the course's `AGENTS.md` instead of learned from your project, a skill so general it's just "help me", and a skill that would write `NOTES.md` sections. If you catch one, it's a good entry for "Accepted / changed / rejected."

## 4. Verify

- Open a **new** session. Ask Claude to read `final-project/src/pages/index.astro`, then: "What are this project's rules?" Does it list yours?
- Type `/`: is your skill there? Run it on something real.
- Ask for something one rule forbids (a link with a leading slash, say). Does Claude object, and quote your rule?

## 5. Explain

Finish `NOTES.md`. For each rule, one line on the moment this term that taught it to you. [`/dig-deeper`](/340/skills/dig-deeper/) on the difference between a rule in `AGENTS.md` and a hook (like the course's scope guard) is a good dig-deeper starting point.

Then run [`/check`](/340/skills/check/) `sparks/s14-configure-agent` and paste in the "done" list above (the **Copy** button copies it).
