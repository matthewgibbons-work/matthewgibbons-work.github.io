# S04 · Type scale

Set the type on the theme palette page you built in S03: one web font with a fallback, sizes in `rem`, roomy line height, and a page that still reads at 200% zoom. Plan on 15–30 minutes. It's due before class on Mon Nov 2 and graded Complete / Not yet straight from your repo, so there's nothing to submit.

It's your practice run for P1, also due Monday, which puts color and typography together on a new page, and for the 200% zoom check every Prototype needs. Work on a copy, so S03 stays as it was. The step most people miss is the browser's font-size setting: zoom makes `px` text bigger too, so only changing the default size shows whether your sizes really follow the reader.

## 1. Intent

Copy your `sparks/s03-theme-palette/` folder to `sparks/s04-type-scale/` (leave S03 as it is). Then write two or three sentences in the new folder's `NOTES.md` **Intent** section: what the type should feel like, and who has to be able to read it. "Fun headings, but body text a grandparent can read without glasses" is a real constraint.

## 2. Spec: the "done" list

Your page is done when:

<!-- done:start -->

- [ ] `sparks/s04-type-scale/` has its own `index.html` and CSS file, and S03 is unchanged.
- [ ] One web font (for example, from Google Fonts) is linked, loading only the weights the page uses.
- [ ] Every `font-family` ends in a fallback stack with a generic family, like `system-ui, sans-serif`.
- [ ] Every `font-size` is in `rem` (or `em` for something that should scale with its parent). No `px` font sizes.
- [ ] Body text has a unitless `line-height` of at least 1.5, and text blocks are capped at about `65ch` wide.
- [ ] No box that holds text has a fixed `height`.
- [ ] At 200% zoom, nothing is cut off, overlapping, or hidden.
- [ ] With the browser's default font size set to 20px, the text gets bigger.
- [ ] The page passes the [W3C validator](https://validator.w3.org/nu/) with no errors.
- [ ] Your hub `index.html` links to it under Sparks.
- [ ] `NOTES.md` covers every section, in your own words.
- [ ] It's committed with a meaningful message, pushed, and the live page loads.

<!-- done:end -->

## 3. Generate

Give the agent your intent and the "done" list, and ask it to propose a type scale (the sizes for body text and each heading level) before it writes CSS. Ask it to explain why each size is in `rem` rather than `px`. If it can't, that's worth a [`/dig-deeper`](/250/skills/dig-deeper/).

**Watch for:** `px` font sizes, a fixed `height` on a header or card, a `font-family` with no fallback, and a font link that loads every weight. If you catch one, it's a great entry for "Accepted / changed / rejected."

## 4. Verify

- Zoom to 200% (Cmd + on a Mac, Ctrl + on Windows, until the browser says 200%). Scroll the whole page. Anything cut off or on top of something else?
- In Chrome, go to **Settings → Appearance → Customize fonts** and set **Font size** to 20. Reload: did your text grow? Set it back to 16 afterwards.
- Count the characters on one line of body text. Roughly 45–75 is comfortable.
- Run the W3C validator on the live URL.

## 5. Explain

Finish `NOTES.md`: what you kept, changed, or rejected and why, one thing you looked up on MDN (`rem` vs `em`, or `font-display`, are good starts), and anything you still don't understand.

Then run [`/check`](/250/skills/check/) `sparks/s04-type-scale` and paste in the "done" list above (the **Copy** button copies it).
