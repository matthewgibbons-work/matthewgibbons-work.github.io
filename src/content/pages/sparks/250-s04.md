# S04 · Type scale

Pick a theme and make a new one-page type specimen for it: one web font with a fallback, sizes in `rem`, roomy line height, and a short "Why these fonts" section that says how each choice fits the theme. Plan on 15–30 minutes. It's due before class on Mon Nov 2 and graded Complete / Not yet straight from your repo, so there's nothing to submit.

It's a new page, not a copy of S03, so all your attention goes on type. You can keep your S03 theme or pick a new one; the reasons are the point. It's also your practice for P1, also due Monday, whose homepage explains its color and type choices the same way. The step most people miss is the browser's font-size setting: zoom makes `px` text bigger too, so only changing the default size shows whether your sizes really follow the reader.

## 1. Intent

Create the new folder `sparks/s04-type-scale/` with its own `NOTES.md` (copy `starter/NOTES.md`, or ask the agent to). Then write two or three sentences in its **Intent** section: the theme, what the type should feel like, and who has to be able to read it. "A 90s arcade: loud, blocky headings, but body text a grandparent can read without glasses" is a real constraint.

## 2. Spec: the "done" list

Your page is done when:

<!-- done:start -->

- [ ] `sparks/s04-type-scale/` has its own `index.html` and CSS file, and it's a new page, not a copy of an earlier Spark.
- [ ] The page names its theme and shows the type in use: headings at three levels (`h1`, `h2`, `h3`), a paragraph of body text, a quote, a list, and a link.
- [ ] A "Why these fonts" section on the page gives a reason from the theme for each font, the heading sizes, and the line height.
- [ ] One web font (for example, from Google Fonts) is linked, loading only the weights the page uses.
- [ ] Every `font-family` ends in a fallback stack with a generic family, like `system-ui, sans-serif`.
- [ ] Every `font-size` is in `rem` (or `em` for something that should scale with its parent). No `px` font sizes.
- [ ] Body text has a unitless `line-height` of at least 1.5, and text blocks are capped at about `65ch` wide.
- [ ] No box that holds text has a fixed `height`.
- [ ] At 200% zoom, nothing is cut off, overlapping, or hidden.
- [ ] With the browser's default font size set to 20px, the text gets bigger.
- [ ] The page passes the [W3C validator](https://validator.w3.org/nu/) with no errors.
- [ ] Your hub `index.html` links to it under Sparks.
- [ ] `NOTES.md` covers every section, in your own words.
- [ ] It's committed with a meaningful message, pushed, and the live page loads.

<!-- done:end -->

## 3. Generate

Give the agent your intent and the "done" list, and ask it to propose two or three font pairings for your theme, with a type scale (the sizes for body text and each heading level), before it writes any HTML or CSS. Pick one, and ask it to explain why each size is in `rem` rather than `px`. If it can't, that's worth a [`/dig-deeper`](/250/skills/dig-deeper/).

Write the "Why these fonts" section from your own reasons. If the agent drafts it, read every sentence and ask: is that why *I* chose it?

**Watch for:** `px` font sizes, a fixed `height` on a header or box, a `font-family` with no fallback, a font link that loads every weight, and reasons that would fit any theme ("clean and modern"). If you catch one, it's a great entry for "Accepted / changed / rejected."

## 4. Verify

- Zoom to 200% (Cmd + on a Mac, Ctrl + on Windows, until the browser says 200%). Scroll the whole page. Anything cut off or on top of something else?
- In Chrome, go to **Settings → Appearance → Customize fonts** and set **Font size** to 20. Reload: did your text grow? Set it back to 16 afterwards.
- Count the characters on one line of body text. Roughly 45–75 is comfortable.
- Read your "Why these fonts" section out loud. Does every reason name something about your theme?
- Run the W3C validator on the live URL.

## 5. Explain

Finish `NOTES.md`: what you kept, changed, or rejected and why, one thing you looked up on MDN (`rem` vs `em`, or `font-display`, are good starts), and anything you still don't understand.

Then run [`/check`](/250/skills/check/) `sparks/s04-type-scale` and paste in the "done" list above (the **Copy** button copies it).
