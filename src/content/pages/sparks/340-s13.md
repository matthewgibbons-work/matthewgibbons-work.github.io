# S13 · Final Project tests

Write Playwright tests for your Final Project: people can do the main thing with the keyboard, the nav says where they are, and axe finds nothing on any kind of page, and each test can fail. Plan on 15–30 minutes after the kit update. It's due before class on Wed Dec 9 and graded Complete / Not yet straight from your repo, so there's nothing to submit. Do the Dec 7 kit update first (step 0).

The tests go in `final-project/`; this Spark's folder holds only its `NOTES.md`. After the kit update, they run on GitHub on every push. Claude is on the **Explanatory** output style: read its `★ Insight`s, and decide. The step most people miss is breaking each test once on purpose: a test that has never gone red hasn't proved anything.

Download [`dight340-update-dec07.zip`](/downloads/dight340-update-dec07.zip) and double-click it. In your `dight340` session, paste:

## 1. Intent

In `sparks/s13-final-project-tests/NOTES.md` **Intent**: what's the one thing a visitor must be able to do on your Final Project, and what would it cost them if it broke?

## 2. Spec: the "done" list

Your Spark is done when:

## 3. Generate

Plan mode first: give Claude the "done" list and your Final Project's intent brief, and ask for a test plan (what each test proves) before any code. Approve the `npm install` only for the two packages above. Then `npx playwright install chromium` once. Write or generate the tests one at a time, and run each before the next.

**Watch for:** CSS selectors instead of roles, `waitForTimeout` instead of waiting for the island, axe rules switched off to get a pass, a test that only checks the page loaded, and no `webServer` in the config. If you catch one, it's a good entry for "Accepted / changed / rejected."

## 4. Verify

- `npx playwright test`, then break one thing per test and run again. Does the right test fail, with a message you can understand?
- `npx playwright test --repeat-each 10` on the island test. Ten passes?
- After you push: **Actions** → **Checks** → the Playwright step. Green? If not, read which test and which axe rule.
- Do your main task yourself with VoiceOver (Cmd+F5). Anything the tests didn't notice?

## 5. Explain

Finish `NOTES.md`. Include one locator read aloud as a screen reader would announce it, and what axe can't check on your site. [`/dig-deeper`](/340/skills/dig-deeper/) on why Playwright recommends `getByRole` is a good dig-deeper starting point.

Then run [`/check`](/340/skills/check/) `sparks/s13-final-project-tests` and paste in the "done" list above (the **Copy** button copies it).
