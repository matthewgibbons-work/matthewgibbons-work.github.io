# P1 · Async party

**Units:** Async 1 (Mon Oct 26: event loop, Promises, `Promise.all`) and Async 2 (Wed Oct 28: `async`/`await`, `fetch`, JSON, error handling). No late penalty; rework is welcome until Dec 9.

## The brief

Build a party page that loads real data from [PokéAPI](https://pokeapi.co/). A user can see a party of up to six Pokémon (name, sprite, and types) fetched live, and can add one more by name. The network is slow and people make typos, so the page has to handle waiting and failure well, and tell *everyone* what's happening, including screen-reader users.

Own-choice option: another free, no-key JSON API, by proposal to the instructor first.

## Spec: the "done" list

<!-- done:start -->

**Async and data**

- [ ] The starting party loads with `fetch`, fetching all members **in parallel** with `Promise.all` (not one after another).
- [ ] Uses `async`/`await`, with `try`/`catch` around network calls. It checks `response.ok`, not just whether `fetch` threw.
- [ ] Shows each Pokémon's name, sprite (with `alt` text), and types, built from the JSON with DOM methods.
- [ ] A labeled form adds a Pokémon by name. It handles a name that doesn't exist with a clear message, not a console error.

**States people can perceive**

- [ ] A visible loading state while data is on its way.
- [ ] Loading, success, and error messages are announced to screen readers (for example, an `aria-live="polite"` region).
- [ ] The add button can't be pressed twice while a request is in flight (or a double press does no harm).

**Every Prototype**

- [ ] Vanilla JavaScript in a file loaded with `defer` or `type="module"`. No libraries.
- [ ] `const`/`let` and `===` only. No console errors when the page loads, adds, or fails.
- [ ] Works with the keyboard alone. Focus stays visible.
- [ ] Readable at 200% zoom (Cmd/Ctrl +): nothing cut off, overlapping, or hidden.
- [ ] Linked from your hub under Prototypes. Live page loads.
- [ ] `NOTES.md` covers every section, in your own words. Meaningful commits.

<!-- done:end -->

**Stretch goal (one way to reach Exceeds):** when one starting Pokémon fails to load, show the others anyway, using `Promise.allSettled`, and explain in `NOTES.md` why `Promise.all` alone wouldn't.

## Working in the loop

1. **Intent:** who uses this page, and what do they need from it? Write it in `NOTES.md` first.
2. **Spec:** start from the list above.
3. **Generate:** plan mode first, then small steps: fetch one Pokémon, then the party, then the form, then the states. Under the Learning style, Claude will leave a `TODO(human)` for some decisions (error handling is a likely one). Write those yourself.
4. **Verify:** open the console, throttle the network in DevTools (Network → Slow 4G) to see your loading state, try a misspelled name, test with the keyboard, and zoom to 200%. Turn on VoiceOver or NVDA briefly to hear the announcements.
5. **Explain:** finish `NOTES.md`, then run [`/check`](/340/skills/check/) `prototypes/p01-async-party` and paste in the "done" list (the **Copy** button copies it).

**Watch for:** sequential `await`s in a loop where `Promise.all` was asked for, missing `response.ok` checks, `.then()` chains mixed with `async`/`await`, errors only logged to the console, and sprites with no `alt`.
