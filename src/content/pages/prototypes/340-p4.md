# P4 · Team planner

**Units:** Svelte components and props (Mon Nov 16) and Svelte forms and shared state (Wed Nov 18). No late penalty; rework is welcome until Dec 9. It's also a good first piece of your [Release](/340/release/): next week it can move into your Astro site as an island.

## The brief

Build a team planner. A trainer adds up to six Pokémon by name, gives each a nickname and a role (attacker, defender, or support), and sees a summary of the team that stays up to date: how many of each role, and which types the team covers. It's P3's party builder grown up: the page is split into components with typed props, the team lives in one shared module that every component reads, and editing a member is a real form, with labels and errors that everyone can perceive.

Own-choice option: another free, no-key JSON API where planning a small group makes sense, by proposal to the instructor first.

## Spec: the "done" list

<!-- done:start -->

**Components and props**

- [ ] `prototypes/p04-team-planner/` is a Svelte 5 + Vite project in JavaScript (TypeScript only for typed props), with `base: './'` and no template leftovers.
- [ ] At least four components, for example `TeamList`, `TeamMember`, `MemberForm`, and `TeamSummary`. Each component's props are typed with an `interface Props`.
- [ ] Children tell their parent what happened through callback props. No component changes data it was only handed (no `ownership_invalid_mutation` warnings in the browser console).
- [ ] One layout component renders `children` in a `<section>` labelled by its heading.

**Shared state**

- [ ] The team lives in a `.svelte.js` module (an exported object whose properties change), imported by at least two components. Nothing copies it into a second `$state` with an `$effect`.
- [ ] The team's rules (at most six, no duplicates, a nickname of 1–12 characters) are plain functions with Vitest tests.

**The form**

- [ ] Editing a member uses a form with `bind:value` for the nickname and `bind:group` (radio buttons in a `<fieldset>` with a `<legend>`) for the role. Every control has a visible `<label>`.
- [ ] On an invalid submit: an error in words next to the field, `aria-invalid` and `aria-describedby` on the input, the error announced, and focus on the first field to fix.
- [ ] Adding by name fetches from PokéAPI with a `response.ok` check, loading and error states, and an announced result.

**Every Prototype**

- [ ] `const`/`let` and `===` only. No console errors, and no warnings in the terminal or the browser console. The **Checks** run is green.
- [ ] Works with the keyboard alone. Focus stays visible.
- [ ] Readable at 200% zoom (Cmd/Ctrl +): nothing cut off, overlapping, or hidden.
- [ ] Linked from your hub under Prototypes. The **Build and deploy** run is green and the live page loads.
- [ ] `NOTES.md` covers every section, in your own words. Meaningful commits.

**Stretch goal (one way to reach Exceeds):** a type-coverage section in the summary: which of the 18 types your team has, and which it doesn't, as text, computed by a tested function from the types PokéAPI returns. Explain in `NOTES.md` how you tested it without calling the API.

## Working in the loop

1. **Intent:** who plans teams, and what do they need to see while they do it? Write it in `NOTES.md` first.
2. **Spec:** start from the list above.
3. **Generate:** plan mode first, and ask for the plan as a list of components with each one's props and callbacks, and which ones import the shared module. Then: the rules module and tests, the shared module, the list and members with hard-coded data, the summary, the form, and last the fetch. Under the Learning style, Claude will leave `TODO(human)`s (a validation rule, or which component owns focus); write those yourself.
4. **Verify:** submit the form empty, too long, and with only spaces, keyboard only, with VoiceOver on (Cmd+F5); rename someone and watch the summary; add seven and a duplicate; keep both consoles open; zoom to 200%; check both runs in **Actions**.
5. **Explain:** finish `NOTES.md`, then run [`/check`](/340/skills/check/) `prototypes/p04-team-planner` and paste in the "done" list (the **Copy** button copies it).

**Watch for:** placeholders instead of labels, errors shown only in red, a child mutating its props, `$effect`s copying state between components, an exported `let` that Svelte refuses to build, and Svelte 4 syntax (`export let`, `createEventDispatcher`, `on:submit`).
