# P2 · Stat card

Build a Svelte stat card for a trainer: type a Pokémon's name and see its sprite, types, and base stats, plus a few things worked out from them (the total, the strongest stat), with that working-out in a module you've tested. It's due Mon Nov 9, with no late penalty. Submit by pasting two links in Learning Suite. Meets means every "done" item; Exceeds adds one extra. Rework until Dec 9.

It builds on Modules and Vite (Mon Nov 2) and Svelte intro (Wed Nov 4); the fetching follows P1: check `response.ok`, show loading and errors, and announce them. Under the Learning style, write any `TODO(human)` yourself (a test or a derived value is likely). Svelte's `{#each}` and `{#if}` blocks are Monday Nov 9's topic; Claude will probably use them now, which is fine as long as you can say what each block does. The step most people miss is keeping the maths in `stats.js`, not the component, so the tests cover it. Own-choice option: another free, no-key JSON API with numbers worth summarizing, by proposal to the instructor first.

## The brief

Someone types a Pokémon's name and sees its sprite, types, and base stats, plus anything else a trainer would want at a glance. The working-out lives in a plain JavaScript module with Vitest tests, so you know it's right before the page ever shows it.

## Spec: the "done" list

<!-- done:start -->

**Modules and tests**

- [ ] `prototypes/p02-stat-card/` is a Svelte 5 + Vite project in JavaScript, with `base: './'` and no template leftovers.
- [ ] A plain module (for example `src/stats.js`) exports at least three functions that take PokéAPI data and return something to show: the total, the strongest stat, a readable stat name (`special-attack` → "Special Attack"), or your own. It never touches the page.
- [ ] Vitest tests cover every exported function, using a small sample of real PokéAPI data copied into the test, with at least one edge case (a tie for strongest, a hyphenated name).
- [ ] `npx vitest run` passes, and the **Checks** run on GitHub is green.

**Svelte**

- [ ] The current Pokémon and the name being typed are `$state`; the worked-out values are `$derived` from them, using your module's functions.
- [ ] No `$effect` sets state. Any `$effect` reaches outside the component, and `NOTES.md` says why.
- [ ] Svelte 5 syntax only (`onclick`, `onsubmit`; no `on:`, `export let`, or `$:`).

**Data and states people can perceive**

- [ ] A labeled form looks a Pokémon up by name with `fetch`, `async`/`await`, and a `response.ok` check.
- [ ] Loading and error messages are visible and announced (an `aria-live` region that's on the page from the start).
- [ ] Stats are shown as text, not only as bar lengths or colors.

**Every Prototype**

- [ ] `const`/`let` and `===` only. No console errors, and no Svelte warnings in the terminal.
- [ ] Works with the keyboard alone. Focus stays visible.
- [ ] Readable at 200% zoom (Cmd/Ctrl +): nothing cut off, overlapping, or hidden.
- [ ] Linked from your hub under Prototypes. The **Build and deploy** run is green and the live page loads.
- [ ] `NOTES.md` covers every section, in your own words. Meaningful commits.

**Stretch goal (one way to reach Exceeds):** show the stats as bars as well as numbers, drawn with plain CSS or SVG, with each bar's value in text that a screen reader reads, and explain in `NOTES.md` how you checked that.

## Working in the loop

1. **Intent:** who looks Pokémon up, and what do they want to know fast? Write it in `NOTES.md` first.
2. **Spec:** start from the list above.
3. **Generate:** plan mode first, then small steps: the project, then `stats.js` and its tests (run them; break one on purpose), then a card with hard-coded data, then the form and `fetch`.
4. **Verify:** run the tests, look a few Pokémon up (including a typo and one with a hyphen, like `mr-mime`), throttle the network (Network → Slow 4G) to see your loading state, use the keyboard only, zoom to 200%, and check both runs in the **Actions** tab.
5. **Explain:** finish `NOTES.md`, then run [`/check`](/340/skills/check/) `prototypes/p02-stat-card` and paste in the "done" list (the **Copy** button copies it).

**Watch for:** maths written inside the component instead of the module (so the tests don't cover it), tests that copy the function's own logic, an `$effect` that copies one state into another, stats shown only as colored bars, and no `base: './'` (a blank live page).
