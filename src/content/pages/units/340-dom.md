# DOM, re-run

**The big idea:** the page is a picture of your data. Change the data, then redraw the picture. Never the other way round.

## In short

Your party lives in a JavaScript array. A `render()` function turns that array into elements with `createElement` and `textContent`, and puts them on the page. Each party member gets a real `<button>`, so a mouse, Tab, Enter, and Space all work with no extra code. A click changes the **array**, not the page, and then calls `render()` again. Two things are easy to lose along the way. One is safety: building HTML strings with data in them (`innerHTML`) lets the data become markup. The other is focus: when an item's button is removed, keyboard focus falls back to the top of the page unless you put it somewhere sensible. This data → render → event → data cycle is exactly what Svelte automates in November, so it's worth seeing by hand once.

## Predict, then reveal

<details>
<summary>You Tab to a party member's Remove button and press Enter. The item disappears. Where is keyboard focus now?</summary>

Usually nowhere useful. The focused button was removed from the page, so focus falls back to the `<body>`, and the next Tab starts again from the top. Decide where it should go instead (the next member's Remove button, or the list's heading if the list is now empty), and call `.focus()` on it after `render()`. That's one line of the S02 "done" list.

</details>

## Live build

We'll ask Claude, in plan mode, with no "done" list:

```text
Show my party array on the page, with a remove button for each Pokémon.
```

<details>
<summary>What went wrong, and how we caught it</summary>

Requests like this often come back with one or more of these:

- A clickable `<div>` or `<span>` instead of a `<button>`, so Tab skips it and Enter does nothing.
- One big `innerHTML` template string with the names dropped straight in, so a name like `<img src=x onerror=alert(1)>` would become markup.
- Removing an item leaves focus on nothing.

The mouse test passed. Tab-through didn't: we put the mouse away and used only Tab, Enter, and Space, then held the code up against the "done" list.

</details>
