# The DOM

**The big idea:** the page is a picture of your data. Change the data, then redraw the picture. Never the other way round.

## In short

The DOM is the live tree of objects the browser builds from your HTML, and JavaScript changes the page by changing that tree: find, make, put, listen. For S02 you need a page that builds your party from a JavaScript array with `createElement` and `textContent`, gives each member a real `<button>`, changes the array (not the page) on a click and redraws, and keeps focus somewhere sensible after a remove.

## What the DOM is

When the browser loads your HTML, it builds a tree of objects from it: one object for each element and each piece of text. That tree is the **DOM** (Document Object Model), and `document` is its root. JavaScript can't edit your HTML file, but it can change the tree, and the browser redraws the page to match. DevTools' **Elements** panel shows the live tree. **View Source** shows the file it started from.

Almost everything you'll do with the DOM is one of four moves:

```js
// 1. Find an element that's already on the page.
const list = document.querySelector('#party');

// 2. Make a new element and give it text.
const item = document.createElement('li');
item.textContent = 'Pikachu';

// 3. Put it in the tree, so it appears on the page.
list.append(item);

// 4. Listen for something to happen to it.
item.addEventListener('click', () => {
  console.log('clicked');
});
```

Try the first three in the console on any page you've built: open DevTools, find an element, make one, and put it in. Watch it appear in Elements.

<details>
<summary>You add an item from the console, then reload the page. Is it still there?</summary>

No. The DOM is rebuilt from the HTML file on every load, and the console changed the tree, not the file. That's why pages keep their data in JavaScript and build the elements from it each time: the data is the thing that lasts, and the page is redrawn from it.

</details>

## How it works

Your party lives in a JavaScript array. A `render()` function turns that array into elements with `createElement` and `textContent`, and puts them on the page. Each party member gets a real `<button>`, so a mouse, Tab, Enter, and Space all work with no extra code. A click changes the **array**, not the page, and then calls `render()` again. Two things are easy to lose along the way. One is safety: building HTML strings with data in them (`innerHTML`) lets the data become markup. The other is focus: when an item's button is removed, keyboard focus falls back to the page itself unless you put it somewhere sensible. This data → render → event → data cycle is exactly what Svelte automates in November, so it's worth seeing by hand once.

## Predict, then reveal

<details>
<summary>You Tab to a party member's Remove button and press Enter. The item disappears. Where is keyboard focus now?</summary>

Usually nowhere useful. The focused button was removed from the page, so focus falls back to the `<body>`. A screen reader announces nothing, and pressing Enter again does nothing. Most browsers remember roughly where you were, so the next Tab often lands on the next button, which hides the problem. Decide where it should go instead (the next member's Remove button, or the list's heading if the list is now empty), and call `.focus()` on it after `render()`. That's one line of the S02 "done" list.

</details>
